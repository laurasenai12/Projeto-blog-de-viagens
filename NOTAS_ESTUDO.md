Qual a diferença entre um projeto de software e um código isolado? 
Um código isolado é uma programação feita para resolver um problema pontual e específico, sem grandes preocupações com organização ou reutilização futura. Já um projeto de software é uma solução estruturada, pensada para crescer, ser mantida e usada por várias pessoas ao longo do tempo. 

Explicar as quatro fases de um projeto:
Levantamento de requisitos: É a etapa inicial, onde vou entender o que precisa ser feito antes de começar a programar. O primeiro passo é conversar com o cliente ou as pessoas que vão usar a programação para descobrir as necessidades, o que esperam. É preciso fazer um documento com os requisitos funcionais (o que o sistema deve fazer) e não funcionais (desempenho, segurança, usabilidade). 

Desenvolvimento: É a fase onde o código é escrito, com base no que foi levantado na etapa anterior. Aqui começa as decisões de arquitetura, escolha das tecnologias, criação de banco de dados, implementação das funcionalidades. Geralmente essa parte é dividida em pequenas partes (sprints, no caso de metodologias ágeis) para fazer ajustes ao longo do projeto.

Testes: Antes de entregar o software, é preciso verificar se ele realmente funciona como esperado. Isso inclui testes unitários (verificam partes isoladas do código), testes de integração (verificam se os módulos funcionam bem juntos) e testes de usuário (verificam se atende às necessidades reais). O objetivo é encontrar e corrigir bugs, falhas de segurança ou comportamentos inesperados para que quando a pessoa for usar estar tudo certo.

Entrega: Aqui o software já está pronto pra usar, seja publicado em produção, instalado no ambiente do cliente ou lançado em uma loja de aplicativos. Muitas vezes essa fase também inclui treinamento dos usuários, documentação final e um suporte depois que fizer a entrega para corrigir problemas que só aparecem quando for usar. 


Por que definir um escopo fechado antes de iniciar a codificação é vital para evitar atrasos na entrega de um software?
Definir o escopo antes de programar evita retrabalho, já que fica claro o que realmente precisa ser feito. Também ajuda a controlar prazos e orçamento, porque as estimativas ficam mais realistas quando se sabe exatamente o que vai ser entregue. Ele também alinha as expectativas entre cliente e equipe, servindo como referência para saber se o projeto foi entregue como combinado.
